Twinly Privacy Policy

Effective date: September 16, 2026
Developer: Team Sapphire
Privacy contact: sushdevv05@gmail.com

This Privacy Policy describes the current behavior of the Twinly Flutter application and its connected services.

1. Information Twinly processes

Account and profile information

Twinly uses Firebase Authentication for email/password sign-up, sign-in, password reset, sign-out, and Firebase account deletion. The app stores the entered name, email address, and gender preference locally on the device using SharedPreferences.

The app also stores fashion and avatar information locally, including height, shoulder width, bust/chest, waist, hip, inseam, body frame, skin tone, hair type, hair color, fit preference, style preference, and budget. The app's current profile implementation does not use a Firestore client or a Firebase Storage client.

When profile onboarding is completed, the app attempts to send the fashion profile to the Express API at POST /api/profile. The server writes that request body to a UID-scoped file under server/data/profiles/.

Saved looks and usage data

Saved fashion looks, including their generated image URL, garment information, fit-guide result, identifier, and creation time, are stored locally with SharedPreferences. Usage-limit counters and avatar profiles are also stored locally.

Garment images and generated previews

If you choose to upload a garment image, Twinly reads the image from the device and sends its bytes to the Express API for garment analysis. If you provide a product URL, Twinly sends that URL to the API instead.

When you generate a try-on preview, Twinly can send the garment image bytes, fashion profile, garment data, and optional garment URL to the Express API. The API processes the request using its configured provider integrations and returns an image URL. Twinly stores that returned URL in the local saved-look record when you save the look.

The repository does not establish how long an external image-generation provider retains uploaded inputs or generated outputs. Twinly does not control those retention terms.

Purchases and subscriptions

When RevenueCat is enabled on a supported native platform, Twinly configures the RevenueCat SDK, requests customer information and offerings, processes purchases, restores purchases, and listens for customer-information updates. The entitlement identifier is:

twinly_pro

Twinly does not pass fashion measurements or image bytes directly to RevenueCat. RevenueCat's own privacy policy and applicable app-store terms govern the purchase and subscription data it processes.

Analytics and crash reporting

There are no analytics or crash-reporting SDKs in this build.

Merchant and affiliate links

There are no merchant or affiliate links in this build.

2. How Twinly uses this information

  • Authenticate users and manage Firebase accounts.
  • Build and update local avatar and fashion profiles.
  • Calculate fit-guide recommendations.
  • Analyze selected garment images or product URLs.
  • Request generated try-on previews.
  • Display and locally save generated looks.
  • Enforce local free-tier usage limits.
  • Determine premium access through RevenueCat when enabled.

3. Sharing and service providers

Depending on the feature and configuration, information may be sent to Firebase Authentication, Twinly's Express API, the image-generation or garment-analysis providers configured by that API, and RevenueCat and the relevant app store for purchases and entitlement status.

4. Local storage and retention

Profile data, avatar data, usage counters, and saved-look records are stored in local app storage through SharedPreferences. They may remain on the device until the account-deletion workflow, app data removal, or uninstall.

The authenticated DELETE /api/account endpoint removes the user's UID-scoped server profile. The repository has no automatic retention schedule for server data.

5. Deletion and account requests

In-app deletion sends the current Firebase ID token to the authenticated server deletion endpoint, deletes the Firebase Auth user, and clears the local name, email, gender preference, fashion profile, saved looks, saved profiles, active profile ID, usage counters, and last garment. If Firebase requires recent authentication, the app requests the password and retries with email/password reauthentication. In Demo Mode, only local data is cleared.

Third-party image-provider data may not be immediately deletable because provider retention and deletion controls are outside Twinly's control. See the account deletion instructions for in-app and email requests.

6. Security

Twinly uses the security mechanisms provided by Firebase, RevenueCat, HTTPS-capable APIs, and configured hosting/provider environments. No method of transmission or storage can be guaranteed to be completely secure.

7. Children's privacy

Twinly is not intended for use by anyone under 16 years of age. We do not knowingly collect information from children under 16. If we learn that we have collected data from a child under 16, we will delete it.

8. Changes to this policy

Twinly may update this policy when the implementation, connected services, or legal requirements change. The updated policy will include a new effective date.
